# AWS EC2 (Elastic Compute Cloud)

## Hva er EC2?

Amazon Elastic Compute Cloud (EC2) er en webtjeneste som gir skalerbar datakapasitet i skyen. Det gjør det mulig for brukere å kjøre virtuelle maskiner kalt instanser, og gir fleksibilitet og kontroll over skymiljøet deres.

---

## Hva brukes EC2 til?

1. **Kjøring av applikasjoner**: Kjør applikasjoner som webservere, applikasjonsservere, eller databaser.
2. **Test og utvikling**: Sett opp miljøer for testing og utvikling av applikasjoner.
3. **Batchbehandling**: Kjør store batchjobber, som dataanalyse og bildebehandling.
4. **Big Data og maskinlæring**: Utfør databehandlingsintensive oppgaver ved hjelp av høyytelsesinstanser.
5. **Skalerbarhet**: Skaler opp eller ned kapasitet basert på behov.

---

## Nøkkelkomponenter i EC2

### 1. **Innstanstyper**

- **Hva:** Forhåndsdefinerte konfigurasjoner for CPU, minne, lagring og nettverk.
- **Bruk:** Velg en instanstype som passer til applikasjonens behov:
  - **Generelle formål**: Balansert CPU, minne og nettverk (f.eks. `t2.micro`).
  - **Databehandling**: For CPU-intensive oppgaver (f.eks. `c5.large`).
  - **Minneoptimalisert**: For applikasjoner som trenger mye RAM (f.eks. `r5.large`).
  - **Lagringsoptimalisert**: For applikasjoner med behov for rask lokal lagring (f.eks. `i3.large`).

### 2. **Amazon Machine Images (AMI)**

- **Hva:** En mal som brukes for å opprette instanser.
- **Bruk:** Velg AMI-er som inkluderer operativsystemer, programvare og konfigurasjoner.

### 3. **Elastic Block Store (EBS)**

- **Hva:** Vedvarende lagring som kan kobles til EC2-instansene.
- **Bruk:** Lagre data som varer lenger enn instansens levetid.

### 4. **Elastic IP (EIP)**

- **Hva:** En statisk offentlig IP-adresse.
- **Bruk:** Koble en fast IP-adresse til en instans.

### 5. **Sikkerhetsgrupper**

- **Hva:** En virtuell brannmur for EC2-instansen.
- **Bruk:** Kontrollér trafikk til og fra instansen ved hjelp av regler.

### 6. **Nettverk (VPC)**

- **Hva:** EC2-instansene kjøres inne i en VPC.
- **Bruk:** Tilpass nettverksarkitekturen for instansene.

### 7. **Auto Scaling**

- **Hva:** Dynamisk skalering av antall instanser basert på belastning.
- **Bruk:** Oppretthold ytelsen ved å automatisk skalere opp eller ned.

### 8. **Load Balancing (ELB)**

- **Hva:** Fordeler trafikk til flere instanser.
- **Bruk:** Sikrer høy tilgjengelighet og distribuerer belastningen jevnt.

### 9. **Key Pairs**

- **Hva:** Nødvendig for sikker tilgang til instanser via SSH.
- **Bruk:** Opprett og bruk nøkler for autentisering.

### 10. **Spot Instances**

- **Hva:** Ubrukte EC2-instanskapasiteter tilgjengelig til lavere priser.
- **Bruk:** For kostnadseffektive oppgaver som tåler avbrudd.

---

## Typer EC2-instanskostnader

1. **On-Demand Instances**: Betal for datakapasitet uten langsiktige forpliktelser.
2. **Reserved Instances**: Rabatt for langsiktig bruk.
3. **Spot Instances**: Lavere kostnader for utnyttelse av ubrukt kapasitet.
4. **Savings Plans**: Fleksible betalingsalternativer med rabatter.

---

## Typiske scenarier

- **Web hosting**: Kjør enkle eller komplekse webapplikasjoner.
- **Big Data-behandling**: Bruk EC2 for databehandling og analyse.
- **Maskinlæring**: Trening og kjøring av modeller på GPU-optimaliserte instanser.
- **Midlertidige arbeidsbelastninger**: Testmiljøer eller andre oppgaver som krever skalerbare ressurser.

---

## Fordeler med EC2

- **Fleksibilitet**: Velg instanstyper og AMI-er basert på applikasjonskrav.
- **Skalerbarhet**: Skaler opp eller ned etter behov.
- **Kostnadseffektivitet**: Velg betalingsmodeller som passer til arbeidsbelastningen.
- **Sikkerhet**: Sikker tilgang og kontroll over instanser.
- **Integrasjon**: Sømløs integrasjon med andre AWS-tjenester.

Med AWS EC2 får du den fleksibiliteten og kontrollen du trenger for å bygge og skalere applikasjoner i skyen

## SSH og Tilkobling til AWS EC2

## Hva er SSH?

Secure Shell (SSH) er et nettverksprotokoll som lar deg få sikker tilgang til en fjernmaskin over et usikkert nettverk. SSH krypterer kommunikasjonen mellom klienten og serveren, noe som gjør det sikkert for oppgaver som filoverføring og fjernadministrasjon av servere.

---

## Hvordan bruke SSH for å koble til en EC2-instans

### Forutsetninger

1. En EC2-instans kjører på AWS.
2. En privat nøkkelfil (`.pem`) som du har lastet ned under opprettelsen av nøkkelen i AWS.
3. Tilgang til SSH-klient (vanligvis innebygd i Linux og macOS; kan installeres som en del av Git Bash eller PuTTY på Windows).

---

### Opprett en privat nøkkel (.pem-fil) på EC2

Når du oppretter en nøkkel på AWS, lastes den ned som en `.pem`-fil. Sørg for å oppbevare denne filen trygt, da den gir tilgang til EC2-instansen din.

---

## Endre Filrettigheter for `.pem`-filen

Filen må ha riktige tillatelser (kun lesetilgang for eieren) for å kunne brukes med SSH.

### Linux og macOS

1. Naviger til mappen der `.pem`-filen ligger:

   ```bash
   cd /path/to/your/pemfile
   ```

2. Endre tillatelsene til filen:

   ```bash
   chmod 400 your-key-file.pem
   ```

3. Verifiser filrettighetene:

   ```bash
   ls -l your-key-file.pem
   ```

   Outputet skal vise: `-r--------`.

### Windows (PowerShell)

1. Naviger til mappen der `.pem`-filen ligger:

   ```powershell
   cd C:\path\to\your\pemfile
   ```

2. Endre tillatelsene ved hjelp av `icacls`:

   ```powershell
   icacls your-key-file.pem /inheritance:r
   icacls your-key-file.pem /grant:r YOUR_USER:(R)
   ```

3. Verifiser filrettighetene:

   ```powershell
   icacls your-key-file.pem
   ```

---

## Koble til EC2 med SSH

### Slik kobler du til

1. Finn den offentlige IP-adressen til EC2-instansen din fra AWS Management Console.
2. Bruk følgende SSH-kommando for å koble til instansen:

#### Linux og macOS

   ```bash
   ssh -i /path/to/your-key-file.pem ec2-user@<public-ip-address>
   ```

- `-i`: Angir nøkkelfilen.
- `ec2-user`: Standardbrukeren for Amazon Linux.
- `<public-ip-address>`: EC2-instansens offentlige IP-adresse.

#### Windows (PowerShell/Git Bash)

   ```bash
   ssh -i C:\path\to\your-key-file.pem ec2-user@<public-ip-address>
   ```

### Feilsøking

- **Tillatelse nektet**: Sjekk at `.pem`-filen har riktige tillatelser.
- **Timeout**: Sjekk at sikkerhetsgruppen til EC2-instansen tillater SSH-trafikk (port 22).

---

## Sikkerhetstips

1. Oppbevar `.pem`-filen trygt og del den aldri med andre.
2. Deaktiver root-tilgang og bruk en bruker med sudo-rettigheter for ekstra sikkerhet.
3. Bruk en brannmur for å begrense hvem som kan få tilgang til port 22.

---

Ved å bruke SSH med en `.pem`-fil kan du få sikker tilgang til EC2-instansene dine og administrere dem effektivt.
